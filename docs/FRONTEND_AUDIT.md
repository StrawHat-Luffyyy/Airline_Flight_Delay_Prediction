# Frontend audit (`web/`)

Date: 2026-10-11. Scope: an audit only. No `web/` source was changed for this document. The only `web/` change in the Phase 0 review is `"strict": true` in `web/tsconfig.json` (see DECISIONS.md). Method: I read every file under `web/src`, `web/index.html`, `web/package.json` and `web/vite.config.ts`. I ran the Impeccable design detector over `web/src`. I also inspected the running app (`npm run dev`, `http://localhost:5173`) in a browser at desktop width and at 375×812 (emulated mobile).

## 1. Summary

`web/` is a single-page, scroll-driven marketing site ("Holding Pattern"), generated by Google AI Studio. It is visually polished, but it is not the dashboard that PROJECT_OVERVIEW §10 asks for:

- There are no Overview, Causes, Explorer or Model pages and no charts. The only interactive element is a predictor form.
- It makes zero `/api` requests. The predictor returns a deterministic fake result computed from a string hash (verified in the browser: JFK → LHR showed "30%" and "+22 minutes expected delay", and no network request was made).
- Several pieces of copy make claims the project cannot back up: data sources we don't use, a ranking of causes, "expected delay minutes".

Phase 6 must therefore build the five dashboard pages and the typed API client largely from scratch. The visual language (dark, cinematic, Instrument Serif display type) can be retained as the landing/hero layer where it helps.

## 6. Technical audit (Impeccable `audit`)

| # | Dimension | Score | Key finding |
|---|---|---|---|
| 1 | Accessibility | 2 | Word-split headings lose spaces in their accessible name; footer links have 16 px touch targets |
| 2 | Performance | 2 | A 4.2 MB hero MP4 with `preload="auto"`; the WebM listed second is never chosen |
| 3 | Theming | 1 | Colours are hard-coded `rgba(...)`/`#010101` throughout, with no tokens |
| 4 | Responsive | 3 | No horizontal overflow at 375 px; the form stacks cleanly |
| 5 | Implementation integrity | 1 | The core feature is simulated; copy contains false claims; debug logging; an AI Studio fetch shim |
| **Total** | | **9/20** | **Poor**: a major overhaul is needed for the dashboard purpose |

**Implementation integrity verdict: fail.** The look is coherent and product-specific (aviation dusk video, serif display, restrained monochrome). But its central interaction is fabricated and its copy asserts sources and methods the project doesn't use.

### Findings

- **[P0] Fake prediction and fabricated copy.** Covered in §4. It violates CLAUDE.md "every number must come from real data". → Phase 6 (`frontend-integrator`), then `/impeccable clarify` for the copy.
- **[P0] The dashboard pages are missing.** Covered in §5. → `/impeccable shape` for the four new pages in Operate mode, reusing the existing type scale and palette.
- **[P1] Headings built from per-word spans have no spaces in their text.** In the running app, `textContent` reads "Everydelayhasacause…" and "Fewersurprisesatthegate.". `StatementSection` adds an `aria-label`. The `FinalSection.tsx:130` `<h2>` does not, so screen readers may announce a run-together word. (WCAG 1.3.1 / 4.1.2.) → `/impeccable harden`.
- **[P1] AI Studio fetch shim in `index.html:4-18`.** It redefines `window.fetch` and `Window.prototype.fetch` as configurable getters/setters. This is unneeded outside AI Studio, and it lets any script replace `fetch` before our API client runs. Remove it in Phase 6.
- **[P2] Debug `console.log` in production code.** `App.tsx:18`, `HeroSection.tsx:22`, `PageLoader.tsx:23-40`, `PredictorSection.tsx:224`. All appear in the browser console on load.
- **[P2] Hero video weight.** `airplane-dusk.mp4` is 4.2 MB, loaded with `preload="auto"` (`HeroSection.tsx:106`). The `<source>` order is MP4 before WebM (3.5 MB), so browsers that support both never use the smaller file. → `/impeccable optimize`.
- **[P2] Small touch targets on mobile.** Measured at 375 px: footer links "Data" 37×16, "Method" 63×16, "Contact" 70×16, and the menu button 38×38. All are below 44×44. → `/impeccable adapt`.
- **[P2] Scroll-jacked, very tall page.** The document is 9,218 px tall (desktop), because several sections use `h-[300vh]` pinning. That is acceptable for a landing page and hostile for a dashboard. Do not carry this pattern into the dashboard pages.
- **[P2] No design tokens.** Colours and blur values are inline in Tailwind arbitrary values and in `index.css`. → `/impeccable extract` before building the new pages, so they share one token set.
- **[P3] Detector: overused fonts.** The detector flags Geist (`index.css:17`) and Instrument Serif (`index.css:40`). Instrument Serif is used with restraint and gives the site its identity, so I treat that as a soft finding. Geist for body text is fine for a data UI.
- **[P3] External Google Fonts.** These load from `fonts.googleapis.com`. Self-host them if offline demos matter (the project runs locally per §2).

### Positive findings (worth keeping)

- `prefers-reduced-motion` is respected in 8 of 12 components through `useReducedMotion`, with static fallbacks.
- There is a global `:focus-visible` ring (`index.css:8-11`). Form inputs have real `<label htmlFor>` associations (`useId`). The result panel uses `aria-live="polite"` and `aria-busy`.
- The semantic landmarks are correct: `header`, `nav`, `main`, five `section`s with ids, `footer`, and a single `h1`.
- Videos are `muted playsInline` and include a poster. `useVideoVisibility` pauses them off-screen.
- There is no horizontal overflow at 375 px, and the predictor form layout reflows well.
- The visual identity is distinctive, not templated: the dark dusk footage, the serif/sans pairing and the restrained palette are a good base for a branded header and landing on top of the dashboard.

## 7. Recommended Phase 6 approach

1. Remove `@google/genai`, `express`, `dotenv`, `@types/express`, `tsx`, `esbuild`, `metadata.json`, the `index.html` fetch shim, `DISABLE_HMR`, and the debug logs.
2. Add `@tanstack/react-query`, `recharts` and a router. Write `web/src/api/client.ts`, typed only from `@flight-delay/shared` zod schemas, and validate responses.
3. Keep the hero as a compact landing/header. Build Overview, Causes, Explorer, Predict and Model as Operate-mode pages with loading, error and empty states.
4. Rebuild the predictor on the existing glass panel: selects fed by `/api/meta`, an hour select, and a gauge showing `probability` vs `threshold` plus `topFactors`. Drop "expected minutes".
5. Replace every claim in §4 with API-backed numbers or remove it.
6. Before/after verification: run `impeccable detect` and repeat this audit, checking desktop and 375 px in the browser.

## Limitations of this audit

- Touch gestures were not synthesized; mobile checks used an emulated 375×812 viewport in the in-app browser (Chromium).
- I measured no contrast ratios over the moving video backgrounds, because they vary frame by frame.
- On mobile, the hero `<h1>` had not finished its character-reveal animation when I took the screenshot at 4 s, so I did not judge its legibility on mobile.
